# 역할별 코드 설명 가이드

이 문서는 `src/train_explained.py`를 팀원 세 사람이 나눠서 읽고 설명할 수 있도록 정리한 안내서입니다. 실행용 코드는 `src/train.py`이고, `src/train_explained.py`는 같은 로직에 함수별 설명과 역할 태그를 붙인 복사본입니다. 두 파일의 실행 결과는 같습니다. 아래 줄 번호는 현재 `src/train_explained.py` 기준이며, 주석을 수정하면 달라질 수 있습니다.

## 1. 담당 구역

| 담당 | 역할 | 설명할 코드 | 핵심 내용 |
| --- | --- | --- | --- |
| 이서준 | 데이터 검증·전처리 | 상수 정의, `load_survey`, `add_symptom_count` | CSV 검증, 숫자 변환, 중복 제거, 증상 수 파생 |
| 박인찬 | 모델 선택·학습·통합 | `LungCancerTrainer`의 모델 메서드, `train`, `main` | 분할, 기준 모델, 후보 4개, 5-fold CV, 최종 학습, 저장 |
| 유소현 | 평가 지표·결과 정리 | `evaluate_model`, `run()`의 평가·저장 단계 | 정확도·정밀도·재현율·F1·ROC AUC·혼동 행렬, 결과 JSON |
| 공통 | 전체 흐름 | `run()` | 데이터 → 분할 → 모델 선택 → 평가 → 저장 |

코드에서 `[이서준]`, `[박인찬]`, `[유소현]`, `[공통]`을 검색하면 해당 구역으로 바로 이동할 수 있습니다.

## 2. 코드 읽는 순서

1. 상수 정의에서 어떤 열을 입력으로 쓰는지 확인합니다. (`[이서준]`)
2. `load_survey`와 `add_symptom_count`로 데이터가 어떻게 숫자로 바뀌는지 봅니다. (`[이서준]`)
3. `evaluate_model`에서 결과를 어떤 지표로 계산하는지 봅니다. (`[유소현]`)
4. `LungCancerTrainer`의 모델 메서드에서 후보 비교와 학습이 어떻게 이루어지는지 봅니다. (`[박인찬]`)
5. `run()`에서 전체 순서를 다시 확인합니다. (`[공통]`)
6. `train`과 `main`에서 함수 호출과 CLI 인자를 확인합니다. (`[박인찬]`)

## 3. 이서준 — 데이터 검증·전처리

### 설명할 코드

| 위치 | 함수/구역 | 현재 줄 번호 |
| --- | --- | --- |
| 상수 정의 | `TARGET`, `BINARY_FEATURES`, `FEATURES`, `MODEL_FEATURES` | 47~74 |
| 데이터 검증 | `load_survey` | 81~162 |
| 파생 변수 | `add_symptom_count` | 169~190 |
| 전체 흐름의 데이터 단계 | `run()`의 1번, 4번 | `[이서준]` 태그 참고 |

### 설명 포인트

- `load_survey`는 CSV를 읽고 **필수 열, 결측값, 값 범위**를 검사합니다.
- `GENDER`는 F/M을 0/1로, 설문 13개는 1/2를 0/1로, 정답은 NO/YES를 0/1로 바꿉니다.
- 완전히 같은 행은 `drop_duplicates()`로 제거합니다. 같은 사람의 응답이 여러 번 들어가면 모델이 그 행을 과하게 외울 수 있기 때문입니다.
- `AGE`는 1~120 범위인지 확인하고, 설문 응답은 1(아니오) 또는 2(예)인지 확인합니다.
- 각 클래스가 최소 2개 이상인지 확인합니다. `train_test_split(stratify=y)`가 정상 동작하려면 두 클래스가 모두 있어야 합니다.
- `add_symptom_count`는 13개 설문 응답의 합을 `SYMPTOM_COUNT`로 추가합니다. 값은 0~13이고, 정답을 사용하지 않으므로 학습/평가 분할 후에 계산해도 정보 누출이 없습니다.
- 향후 `--predict`를 구현할 때도 `load_survey`의 값 검사 방식을 재사용할 수 있습니다.

### 예상 질문

**Q. 왜 문자열을 숫자로 바꾸나요?**  
A. scikit-learn 모델은 숫자 입력을 받기 때문입니다. F/M, YES/NO, 1/2를 각각 0/1로 바꿔 같은 의미를 유지합니다.

**Q. 중복 행을 왜 제거하나요?**  
A. 완전히 같은 응답이 여러 번 있으면 그 패턴이 학습에 과도하게 반영될 수 있습니다. 검증 단계에서 중복을 제거해 데이터를 깨끗하게 만듭니다.

**Q. 결측값은 어떻게 처리하나요?**  
A. 현재 코드는 결측값이 있으면 `ValueError`로 중단합니다. 임의로 채우지 않고 원본 CSV를 확인하도록 만든 보수적인 방식입니다.

**Q. 증상 수를 추가한 이유는 무엇인가요?**  
A. 개별 문항을 하나씩 보는 것보다 “예” 응답이 몇 개인지 요약하면 위험 신호의 누적을 표현할 수 있습니다. 계산이 간단하고 정답을 사용하지 않아 안전합니다.

## 4. 박인찬 — 모델 선택·학습·통합

### 설명할 코드

| 위치 | 함수/구역 | 현재 줄 번호 |
| --- | --- | --- |
| 실행 설정 | `LungCancerTrainer.__init__` | 248~261 |
| 기준 모델 | `build_baseline` | 263~278 |
| 후보 모델 | `build_candidates` | 280~319 |
| 모델 선택 | `select_model` | 321~371 |
| 선택 모델 생성 | `build_model` | 373~379 |
| 전체 흐름의 모델 단계 | `run()`의 2, 3-1, 5, 6, 10번 | `[박인찬]` 태그 참고 |
| 함수/CLI | `train`, `main` | 493~528 |

### 설명 포인트

- 데이터를 학습 80% / 평가 20%로 나눕니다. `stratify=y`로 두 데이터의 YES/NO 비율을 비슷하게 유지합니다.
- 기준 모델은 `StandardScaler + LogisticRegression`입니다. 스케일러를 Pipeline 안에 넣어 학습 데이터에만 평균·표준편차를 적합합니다.
- 후보는 로지스틱 회귀, KNN(k=5), 랜덤 포레스트, Gradient Boosting 4개입니다.
- `select_model`은 학습 데이터에서만 5-fold `StratifiedKFold`를 수행합니다. 평가 데이터는 모델 선택에 사용하지 않습니다.
- 평균 정확도를 1순위, 평균 F1을 2순위로 비교해 가장 좋은 모델을 고릅니다.
- 선택된 모델을 학습 데이터 전체에 다시 `fit`하고, 평가 데이터는 마지막 평가에만 사용합니다.
- `model.joblib`에는 모델, 입력 특성 순서, 선택 모델 이름을 함께 저장합니다.
- 향후 pytest 기반 통합 테스트와 다른 PC에서의 실행 검증을 담당합니다.

### 예상 질문

**Q. 왜 80:20으로 나누나요?**  
A. 학습 데이터를 충분히 남기면서, 학습에 사용하지 않은 평가 데이터로 일반화 성능을 확인하기 위해서입니다.

**Q. 교차검증은 왜 하나요?**  
A. 한 번의 분할은 운에 따라 점수가 달라질 수 있습니다. 5-fold CV로 여러 번 검증해 평균적인 성능을 비교합니다.

**Q. 평가 데이터를 모델 선택에 쓰면 안 되나요?**  
A. 쓰면 평가 데이터가 선택에 영향을 받아 최종 성능이 낙관적으로 보일 수 있습니다. 그래서 선택은 학습 데이터에서만 합니다.

**Q. 왜 Gradient Boosting이 선택됐나요?**  
A. 5-fold CV 평균 정확도가 0.923으로 네 후보 중 가장 높았습니다. 깊이 2의 단순한 트리 100개를 사용해 작은 데이터에서 과적합을 줄였습니다.

**Q. `random_state=42`는 왜 고정하나요?**  
A. 데이터 분할, 모델 초기화, 교차검증을 실행할 때마다 같게 만들어 결과를 재현하기 위해서입니다.

## 5. 유소현 — 평가 지표·결과 정리

### 설명할 코드

| 위치 | 함수/구역 | 현재 줄 번호 |
| --- | --- | --- |
| 평가 지표 | `evaluate_model` | 197~238 |
| 전체 흐름의 평가 단계 | `run()`의 3-2, 7, 8, 9번 | `[유소현]` 태그 참고 |

### 설명 포인트

- `evaluate_model`은 `predict()`로 0/1 예측을 만들고, `predict_proba()[:, 1]`로 YES 확률을 구합니다.
- 정확도, YES 정밀도, YES 재현율, YES F1, ROC AUC, 혼동 행렬을 계산합니다.
- 혼동 행렬은 행이 실제 값, 열이 예측 값입니다. `[[TN, FP], [FN, TP]]` 순서입니다.
- 정확도만 보면 안 되는 이유는 YES가 86.2%인 불균형 데이터이기 때문입니다. YES를 모두 YES로 예측해도 정확도는 높아 보일 수 있습니다.
- `metrics.json`에는 기준 모델과 선택 모델의 지표, 후보별 CV 평균, 선택 모델 이름이 저장됩니다.
- 아직 시각화 코드는 없지만, 다음 단계에서 혼동 행렬 히트맵, ROC 곡선, 중요도 막대를 만들 예정입니다.

### 예상 질문

**Q. 정확도만 보면 안 되는 이유는 무엇인가요?**  
A. YES가 86.2%로 많기 때문에 모두 YES라고 예측해도 정확도가 높게 나옵니다. 그래서 YES 정밀도·재현율·F1을 함께 봐야 합니다.

**Q. 혼동 행렬은 어떻게 읽나요?**  
A. 행은 실제 NO/YES, 열은 예측 NO/YES입니다. TN은 NO를 NO로 맞힌 수, FP는 NO를 YES로 잘못 예측한 수, FN은 YES를 NO로 놓친 수, TP는 YES를 YES로 맞힌 수입니다.

**Q. 정밀도와 재현율의 차이는 무엇인가요?**  
A. 정밀도는 “YES라고 예측한 것 중 실제 YES의 비율”이고, 재현율은 “실제 YES 중 YES라고 예측한 비율”입니다. 이 프로젝트에서는 놓침(FN)을 줄이는 재현율도 중요합니다.

**Q. ROC AUC는 무엇인가요?**  
A. 예측 확률을 기준으로 YES/NO를 얼마나 잘 구분하는지 나타내는 값입니다. 1에 가까울수록 구분을 잘합니다.

**Q. 시각화는 무엇을 만들 예정인가요?**  
A. 혼동 행렬 히트맵, ROC 곡선, 문항별 중요도 막대를 PNG로 저장할 예정입니다. 발표 자료의 결과 슬라이드와 연결할 수 있습니다.
